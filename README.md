# CSDN Markdown 图片自动上传 — 图随文走

CSDN 的 Markdown 编辑器一键导入 `.md`，**正文和图片一起进来**——图片自动上传到
CSDN 图床并换成直链，不用一张张手动传、也不用再把光标挪回该在的位置。零权限
Chrome / Edge 扩展，代码未压缩未混淆，可逐行审阅。

## 它解决什么

Markdown 往平台编辑器里一贴，文字全好，图全炸。因为正文里的图片是
`images/01-flow.png` 这样的相对路径，或者某个外站直链——编辑器拿到的只是一串字符，
它不会替你去磁盘上找那个文件，更不会替你传到它自己的图床上。

十张图，手动传二十分钟，还容易插错行。这个扩展把这一步变成一次点击。

## 装

1. 下载本仓库（`Code → Download ZIP`，解压）
2. 打开 `chrome://extensions`，右上角开「开发者模式」
3. 「加载已解压的扩展程序」→ 选中解压出来的文件夹

Chrome / Edge 都行。

## 用

1. 打开 CSDN 的 Markdown 编辑器 `https://editor.csdn.net/md`
2. 点工具栏右边的「更多」，菜单最下面多了一条 **导入 MD（自动传图）**
3. 选你的 `.md`；正文里如果有本地图片，按住 <kbd>Ctrl</kbd> 把那些图**一起选上**

然后就没你的事了。底部依次显示「正在上传图片 3/8…」「正在写入正文…」，最后报一句：

```
完成：6 张图已上传，2 张交给 CSDN 转存（稍等看结果），1 张没拿到，已留成文字
```

三种下场分开报，因为它们不是一回事：

| 下场 | 什么情况 | 结果 |
| --- | --- | --- |
| **已上传** | 本地图，或我们在浏览器里 `fetch` 得到的外链图 | 换成 `i-blog.csdnimg.cn` 直链 |
| **交给 CSDN 转存** | 外链图我们 `fetch` 不到（对方没给 CORS 头） | 原样留着，CSDN 服务端自己去抓 |
| **没拿到** | 本地图又没被选中 | 降级成一行文字，不让你莫名其妙少一块 |

> 本地图漏选了不会闷声降级——它会把漏掉的文件名点出来，让你再选一次。
> （做不到直接弹第二个文件框，原因见下面「三个坑」。）

## 它凭什么能自动传图

**不是逆向 CSDN 的上传接口。** 那需要签名和 token，既脆弱又越界，人家改一版参数就全挂。

正路是让 CSDN 自己去传，我们只负责把文件递到它手上。CSDN 的编辑器本来就支持
「粘贴图片自动上传」，而粘贴在浏览器里是一个可以构造出来的事件：

```js
const dt = new DataTransfer();
dt.items.add(file);                       // file 来自 <input type="file">
ed.dispatchEvent(new ClipboardEvent('paste', {
  clipboardData: dt, bubbles: true, cancelable: true,
}));
```

对 CSDN 的监听器来说，这跟你真按下 <kbd>Ctrl</kbd>+<kbd>V</kbd> 没有区别。实测 2.1MB 的
PNG 约 1.9s 传完。

### 关键决定：上传结果从网络层拿，不从正文里认

CSDN 传完图会把 `![](url)` 写回编辑器，但**这一步是坏的**：它先插占位符、记下偏移量，
传完再按那个偏移量替换回去。而合成 `paste` 不走它自己的选区模型，编辑器以为光标还在
上一张图那行——于是第二张的回填落到第一张身上，把 `![…](url)` 啃成光秃秃的
`在这里插入图片描述`。实测 4 张连传，正文里一个链接都不剩，且成功/失败严格交替。

但上传本身**从来没失败过**，而且 OBS 的响应里直接就带最终直链：

```json
{ "code": 200, "data": { "imageUrl": "https://i-blog.csdnimg.cn/direct/<hash>.png" } }
```

所以别跟那个坏掉的回填较劲，**直接问上传要结果**——挂一个只读的 `fetch` / `XHR` 钩子，
看见带 `imageUrl` 的响应就收下（见 `csdn.js` 里的 `HOOK` 那段）。换来三件事：

- 不用为了躲开覆盖而在每张图之前清空编辑器，**你正在写的草稿全程原样待着**
- 判定是精确的：有 `imageUrl` 就是成了，OBS 回了却没有就是没成。不再需要
  「变过又稳住 2 秒」那种靠猜的启发式，也不需要重试兜底，失败不用干等到超时
- 快：13s → 8s，每张稳定 1 秒左右

> **一条走不通的路，写出来省你时间。** 往 CSDN 自己的 `input[type=file]` 里塞
> `input.files = dt.files` 再派发 `change`——**这条路本身是通的，上传照样成功**，
> 但连传三张链接数始终是 1，和合成 paste 一模一样的下场。坏的是回填，不是触发方式。
> 换哪个门进去，里面那个 bug 都在。别再试第二遍。
>
> 顺带说清这个套路真正的边界：它只能喂你手上已有的 `File`，**读不了用户磁盘上的任意
> 文件**。浏览器不允许脚本给 file input 设路径字符串，这是安全底线，没有绕法。

### CSDN 自己会「外链图片转存」，为什么还要我们传

会，而且是**服务端**去抓：粘个 https 图片链接进来，它显示「外链图片转存中…」，抓到就
换成 `i-blog.csdnimg.cn/img_convert/<hash>`。实测 `www.python.org` 的图 7 秒搞定。

但它的服务器够不着的地方就抓不到。实测 `pbs.twimg.com`（X 的图床）那条**永远停在**
`[外链图片转存中...(img-xxx)]`——注意这连图片语法都不是了，发出去就是一行废字。

**墙和防盗链是按「谁在发请求」算的。** 浏览器带着你的网络和身份，CSDN 的服务端没有。
所以两条路互补，不是二选一：我们 `fetch` 得到的自己传，`fetch` 不到的原样留给它转存。

## 三个坑（改代码前先看一眼）

**选中全文直接 paste 覆盖不掉。** CSDN 的 paste 处理走自己的选区模型，结果是**追加**
而不是替换。必须先 `document.execCommand('delete')` 清空再 paste。用 `execCommand`
而不是直接改 DOM 是有意的——它过的是浏览器自己的编辑管线，编辑器的内部模型跟得上。

**不能连着弹第二个文件选择框。** 用户选完 `.md` 我才知道漏了哪几张本地图，但
`change` 事件不算「用户手势」——那一下手势已经花在第一次选文件上了，后续的
`input.click()` 会被浏览器**静默拒掉**，连报错都没有。只能摆一条带按钮的提示，
让用户自己再点一下。

**扫图片的正则会误伤代码块。** 讲 Markdown 的文章会把 `![](…)` 写在反引号或围栏里当
**例子**，那不是图片。实测踩过：一篇讲这个功能的文章，三处示例全被换成「图1：01-xxx.png」
这样的文字，句子当场读不通。修法是先把代码区域挖成**等长**的空白再扫——长度不变，
所以在副本上算出来的下标拿回原文照样对得上：

```js
const maskCode = (md) =>
  md
    .replace(/```[\s\S]*?```/g, (m) => m.replace(/[^\n]/g, ' '))
    .replace(/(^|[^`])(`[^`\n]*`)/g, (m, p, c) => p + c.replace(/[^\n]/g, ' '));
```

同理最后拼正文也不能用 `md.replace()`，得按扫出来的下标逐段切。

顺带一个好处：CSDN 自己写回的 alt 恒定是「在这里插入图片描述」，而我们是先拿 URL
再回填，**原文的 alt 全部保留**。

## 常见问题

**CSDN 的「外链图片转存」不是能自动转存吗，为什么图片还是失效？**
它是服务端去抓图，够不着的图（比如没给 CORS 头的站点、或者反爬严格的图床）会一直卡在
「外链图片转存中…」，最后连图片语法都保不住。这个扩展是在你自己的浏览器里取图再传，
网络环境和登录态跟你手动操作时一样，抓得到的范围更广，两条路可以互补着用。

**从 Typora / Obsidian / VS Code 写好的笔记，能直接搬到 CSDN 吗？**
能。只要是标准 Markdown 加本地图片相对路径这种最常见的写法，选中 `.md` 连同它引用的
图片一起导入即可，正文和图片会一起就位，不用逐张替换链接。

**CSDN markdown 图片上传总是一半成功一半消失，是我的问题吗？**
不是，是 CSDN 编辑器自身「先插占位、按偏移回填」这一步在连续上传时会互相覆盖（本 README
「关键决定」一节有完整分析）。这个扩展绕开了那个坏掉的回填逻辑，改从上传接口的响应里
直接拿链接。

**需要 CSDN 的账号密码或者 API Key 吗？**
不需要。全程借用你已经登录、正在使用的 CSDN 编辑器页面本身的上传功能，扩展不接触你的
账号信息，也没有任何权限去读取它们。

## 隐私

**不收集任何数据。** 没有账号、没有服务器、没有统计、没有远程代码。

零权限——`manifest.json` 里连 `permissions` 字段都没有，只有一条作用于
`editor.csdn.net` 的内容脚本。你选的 `.md` 和图片只在你自己的浏览器里读取，
图片直接传给 CSDN 自己的图床。详见 [PRIVACY.md](PRIVACY.md)。

编辑器）。CSDN 这部分自成一件事、而且零权限，所以拆出来单独发。
